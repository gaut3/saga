## [1.1.0] - 2026-08-09

### Added
- **Android Auto.** Saga now appears in the car, with three shelves: Continue listening, Downloaded, and your collections in the order you dragged them into. Picking a book resumes it where you left off, the same as picking it up at home, and asking for one by name works too — voice being the only sensible way to choose a book while driving. The whole list is built from what's already on the phone, so it doesn't go blank the moment you leave the house and your Plex server behind; a downloaded book plays from the car with no server involved at all. **Untested in an actual car** If you do try it, [say how it went](https://github.com/gaut3/saga/issues).
- **The lock screen's resume card knows what it's resuming.** After Android has closed Saga down, the media card it leaves behind used to be blank. It now carries the book you were last listening to, cover and all, and its play button picks that book back up.

### Changed
- **Browse sorts and History scroll without stutter on large libraries.** Sorting Browse computed each book's sort key over and over *during* the sort — for duration that meant reading the saved position from storage tens of thousands of times on a big library, re-run on every keystroke. Keys are now computed once per book. History's Day and Month tabs similarly re-scanned every book's full session log on every rebuild; the scan now runs once per update and the tabs read the cached result. The downloaded-books list in Settings also stopped blocking the interface while it measures files.
- **One implementation where there used to be copies.** The bookmark naming sheet, the add-to-collection picker, the collection name dialog, the week bar chart, and the "next in series" rule each existed as two or three hand-written copies that had already drifted apart in small ways (different field labels, different bar colours, a second bookmark-id scheme). Each is now a single shared implementation, so the next change lands everywhere at once. Visible side effect: the bookmark sheet's name field now says "Label" in both places it appears, and its Save button looks the same everywhere.
- **Selecting books works in the list view too.** Long-press to select, tap to toggle, checkmarks on the rows — the same as the grid. Before, switching to list view with books selected showed no selection at all, and every tap navigated away while the download bar floated over a list that couldn't answer it.
- **Books can be swiped out of a collection.** In a collection, swipe a row left to remove it — the same gesture that deletes a bookmark in All Bookmarks. Before, the remove button only existed while searching within the collection, because the drag handle occupied its spot the rest of the time.
- **"Avg / day" now means average per day you actually listened, on every tab.** The month view divided by every calendar day — including days that hadn't happened yet — so on the 3rd of a month with three hours listened it said "6m Avg / day" while the Total tab said an hour. All three tabs now share one definition, and the label says "Avg / active day".
- **An author's books now look like every other grid of books.** The page behind an author's name drew its covers tall and cropped rather than square, and left out the progress bar and the downloaded mark that Browse and Home show on the same books — a grid saying less about a book than the grid next door. It now draws the same square card. The bottom row also sat under the mini player and the nav bar with no way to scroll past them; it now clears both. Home, Browse and author pages share one card between them rather than three copies that had quietly drifted apart, so Home's rows carry a slightly lighter title and a slightly larger author line than before, and every strip and grid is now sized from the card itself rather than from a number typed in beside it.
- **A second Plex server no longer inherits the first one's progress.** A book's id is only unique within one server, and Saga filed everything under it — your position, whether you'd finished it, its chapters, its downloaded files. So if you switched to another server, book 12345 there quietly picked up book 12345's position from the server you left: a book you'd never opened sitting four hours in, a cover belonging to something else, or a downloaded file played for the wrong entry. Plex lists servers other people have shared with you right beside your own, so having a second one isn't unusual and switching is two taps. Each server's books are now kept apart, and switching back finds everything where you left it. Nothing moves for anyone with a single server — the first server Saga ever saw keeps filing books exactly as before, so there's no conversion step and no moment where a position could go missing. The same fence covers everything else filed by a book's id: named bookmarks and their notes, each book's saved playback speed, the narrator search index, and the queue of progress reports waiting for an unreachable server — which would otherwise have been delivered, numbers intact, to whichever server answered next. Switching servers or signing out with a book still playing now parks it first, so the rest of that session can't be filed under the new server's idea of the same number. Signing out keeps you scoped to the server you were last using — the one whose downloads are still on the phone — rather than snapping back to the first server Saga ever saw. And when the server Saga knew disappears from your account's list, it no longer silently adopts whichever server Plex lists first — that can be someone else's — it asks you to pick.
- **The privacy policy and the in-app privacy screen now describe what Saga actually does — including the parts that aren't flattering.** Two sections had gone stale: notification artwork hasn't carried your token since earlier in this release, and casting no longer uses your account key where it can avoid it. Both are corrected. Three things that were true all along but had never been written down are now stated plainly: Saga has to tell Android what you're listening to for the lock screen and Android Auto to work, and Android lets other installed apps read that — titles, authors, your downloads and collections, though never a password or an address that reaches your server; the progress export is an unencrypted file containing your notes and listening history, so it deserves the care you'd give a diary; and the random device identifier Plex requires for sign-in outlives signing out, which is what keeps your phone from appearing in your Plex account as a new device every time. The in-app screen also now mentions the optional GitHub update check, which the policy and the README have always listed but it didn't, and names the Google Cast SDK in the acknowledgements — it's the one closed-source component in the app, and a privacy screen that lists only the flattering dependencies isn't worth reading.
- **"Check for updates" now says which of four things happened.** It only ever said "View releases on GitHub", whether it had found you were up to date, failed to reach GitHub, been switched off, or read a release it couldn't make sense of. Those look identical from the outside, so a check that had never once worked was indistinguishable from one working perfectly — and if you run a build newer than the latest release, the quiet outcomes are the only ones you ever see. It now distinguishes up-to-date (with your version), an available update, and a failure, and failures are written to the diagnostics log with the reason.
- **Saga now signs in as "Saga".** The device list in a Plex account showed this app under "AudiobookPlex", the project's working title, which the privacy policy has never used. New sign-ins carry the real name; existing installs keep their device entry, since the identifier behind it doesn't change.
- **The encryption claim now says exactly what it covers.** Three of the four places describing Saga's storage said all local data is AES-256 encrypted. Positions, bookmarks, history and settings are; the downloaded audio files themselves are not — a player has to be able to read them — and their protection is Android's app-private storage, which no other app can reach. The policy, the in-app privacy screen and the store description now draw that line where it actually is, and the in-app screen also gained the one fact it alone omitted: that casting is the single place a key travels in an address rather than a header.

### Fixed
- **A book that failed to load no longer leaves the previous book's player on screen.** Every screen that opens the player pushes it first and loads the book after — that's what makes a tap feel instant — but when the load failed, the player stayed up showing whatever was loaded before, controls working, with at best a brief toast to say why. Home's resume card was worst: tapping its body with the server unreachable opened a blank Now Playing with no message at all. All five launch paths now share one routine that takes the player back down and says what went wrong.
- **Listening past midnight now credits both days.** A session from 23:30 to 00:20 put its start in one day's log and its end in the next day's, so the per-book rows credited it to neither: the day's header said "1h" while every book under it said nothing. Sessions are now split at midnight, each day getting its share, and the expanded session list labels the night session correctly on both days.
- **History's day rows no longer swap their expanded panels at midnight.** Leave History open while listening past midnight and a new day appears at the top of the list — and the panel you'd expanded for yesterday re-attached itself under today's date. Rows now carry their identity with them.
- **Scrubbing in chapter mode no longer jumps to the next chapter's timeline mid-drag.** With chapter scrubbing on, the bar re-anchors to whichever chapter is playing — including while your thumb was holding it, since audio keeps going underneath. Cross a boundary mid-drag and releasing at "90%" seeked to 90% of the *next* chapter. The range is now frozen the moment the drag starts.
- **The chapters sheet keeps up on multi-file books.** The play arrow marking the current chapter was set once when the sheet opened, so when playback rolled into the next file with the sheet up, the arrow stayed behind — while the same sheet on single-file books tracked live. Both track live now.
- **The month view's arrows now mean what they show.** The back arrow never dimmed — its bound compared the shown month against a year before itself, which is always true — so you could page into empty months forever; it now stops at your first recorded listen. And a History screen left open across the turn of the month couldn't page forward into the new month until reopened; the bound now follows the calendar.
- **Tapping a session in History says why nothing happened.** Jumping to a session for a re-imported book, or with the server unreachable, did nothing at all — the dead-button pattern its sibling in All Bookmarks was cured of. It now explains, with the same wording.
- **"Set cover" no longer calls a loading collection empty.** Opening the cover picker before the book list had arrived showed "Add books to this collection first." for a collection with ten books; it now says it's still loading.
- **The finished panel counts days on a calendar.** "Start to finish" measured elapsed 24-hour blocks, so a two-day read across the March DST change counted as one day — the exact mistake the project's own date rules exist to prevent, in the one place still making it.
- **Jumping to a bookmark from the player could move you to the wrong file — and then save that as your place.** A bookmark remembers a position *inside one file*, but the player's own "Jump to" button seeked that offset into whichever file happened to be playing. On a book made of many files, a bookmark saved in file 8 tapped while file 2 played landed you at that minute of file 2 — and ten seconds later the autosave wrote the wrong spot over your real position. Every other way of jumping to a bookmark already resolved the file first; the player's button now does too, and a bookmark pointing into a file that's no longer part of the book says so instead of doing nothing. Single-file books were never affected.
- **The on-screen rewind button couldn't cross backwards into the previous file.** Skip-forward, and the rewind button on the notification and lock screen, treat the book as one long timeline; the rewind button on the player screen alone rewound within the current file and stopped dead at its start — ten seconds into a chapter, "back 30 seconds" went back ten. All four buttons now go through the same shared handler, so they can't disagree again.
- **Dragging a book in a collection could silently delete others from it.** The collection screen can only list books it can resolve in the current library — a book re-imported in Plex under a new id, or one living on another server, is invisible there. Reordering wrote the visible list back as the whole collection, so those invisible entries vanished on the first drag, with no confirmation and no undo. Reordering now moves only what you see and leaves the rest in their places.
- **A deleted bookmark could come back from the dead.** The player's bookmark sheet kept its own copy of the bookmark list, read once and never refreshed, while the All Bookmarks screen wrote straight to storage. Delete a bookmark in one place, edit any bookmark in the other, and the stale copy wrote the deleted one back to disk. Both screens now go through the same list, so a delete is a delete.
- **Restoring a backup left collections and history invisible until a restart.** The restore wrote everything correctly but only told half the app about it — the Collections tab and the History screen kept showing what they'd shown before the import. They now refresh with everything else the moment the restore finishes.
- **Marking a finished book "completed" by hand could count the listen twice.** The book page decided whether a book was completed once, when it opened, and never looked again — so if the book finished in the player while the page sat open on another tab, its button still offered "mark completed", and tapping it recorded a second completion for one listen. The page now reads the live record, the same one the player writes.
- **History could report a nearly-finished book as a few percent done.** The per-day progress bar in History divided a position *inside one file* by the length of the *whole book* — the same mistake the shared progress rule was created to prevent, in the one surface that wasn't using it. A twenty-file book on file twelve showed 3% in History while Home said 60%. It now resolves the file's own offset first, and on the rare occasion it can't, it hides the bar rather than draw a wrong one.
- **"Download" on a multi-selection always claimed success.** Selecting books in Browse and tapping download reported "Queued N books" even fully offline, when nothing had been queued at all. It now says how many actually queued, and when something failed, that the server couldn't be reached.
- **A session with a sleep timer inside it showed no duration in the player's Sessions sheet.** The player, and both of History's per-book panels, each paired play with pause by their own hand-rolled rule, and the player's required the two to sit adjacent in the raw log — which a skip or a sleep timer set in between quietly broke, so the same session showed "42m listened" in History and nothing in the player. All three now share one pairing rule, with tests pinning it down.
- **The lock screen could read "Saga is running" over a book that was playing.** No title, no author, no cover — just Android's placeholder for a player that hasn't said what it's playing, sitting above controls that did still work and a position that was still right. Android is free to shut Saga's playback service down and start a fresh one while the app itself carries on running, and the new one begins knowing nothing about the current book. Everything that changes moment to moment — playing or paused, where you are, how fast — is sent again the instant it changes, so all of that came straight back; the title and cover are only sent when the book changes, and the book hadn't changed. They are now re-sent whenever playback starts and whenever the app is reopened, so the card fills itself back in rather than waiting for the next book.
- **The cover cache grew without limit.** Every cover Saga had ever shown was kept forever, including books long gone from the library, in storage only reachable by clearing all of Saga's data — which would have taken your positions and history too. It's now capped, oldest covers dropped first, and a dropped cover simply reappears next time you open the book.
- **Text fields in the bookmark, rename and new-collection dialogs weren't released when the dialog closed**, and signing in opened a new connection every two seconds while it waited for you to approve the login instead of reusing one.
- **A single unplayable item could sign you out.** Saga treats a refusal from Plex as "your token has expired" and clears it. But a server also refuses individual items for ordinary reasons — a restricted library, a managed user — and Saga couldn't tell the two apart, so one item you weren't allowed to see ended the whole session. Only a refusal that's actually about the token signs you out now.
- **Closing the finished-book panel no longer lets the next book start anyway.** With auto-play on, finishing a book shows a five-second countdown with a Cancel button — but the panel's X only *hid* the panel. The countdown kept running invisibly and the next book started against what was fairly clearly a "no". The X now means the same thing Cancel does.
- **The lock screen's resume card could offer the book you'd just finished.** Finishing a book saves a position at the very end, which made it the most recent bookmark — so the resume card, the car's Continue-listening shelf and the restore-after-Android-kills-Saga path all led with the finished book, and "resuming" it played the last few seconds and finished it again. All three now skip finished books, the same rule Continue Listening on the Home screen has always applied.
- **The book screen now keeps up while its book plays.** The progress bar, the "resume at" figure and the highlighted chapter were read once when the page opened and never again, so with the mini player running they sat frozen while the same book's card on Home ticked along. They now follow the position like every other surface.
- **Changing theme now reaches screens left open on other tabs.** A book page, an author's books, a collection or the bookmarks screen opened earlier kept the old colours until closed — each tab's stack survives in the background and nothing repaints it from above. Those screens now watch the theme themselves, the same fix the downloaded-books tile needed in 1.0.13.
- **Two more buttons stopped failing silently.** Jumping to a bookmark from All Bookmarks, and Resume on the Home card, did nothing at all when the book couldn't be loaded — the dead-button look the finished screen's next-book button was cured of in 1.0.15, on two of its siblings. Both now say what went wrong, and a bookmark pointing into a file that's no longer part of the book says that specifically.
- **A book whose length Plex reports as zero now shows its length in the car.** The Android Auto rows measured length by a rule of their own instead of the shared one that already knows to fall back to the length recorded on first play, or to the downloaded files themselves.
- **Covers stopped flashing grey on the way back from the player.** Every surface decoded covers at its own size — eleven different sizes across the app — and a decoded image is only reusable at the exact size it was decoded at, so the same cover could be instantly there in the mini player and still "loading" on the Home card beside it. The player screen also decoded its full-screen cover at whatever resolution the file held, which for a large cover is enough to push the lists' thumbnails out of memory while you're in there. Covers now share three decode sizes, so any surface that has shown one warms the rest; the big decodes are capped; and the grey placeholder only appears at all once a load has taken long enough to be a real fetch rather than a re-read of a cover the phone already has.
- **One bad moment reading the sign-in credentials could have cost every saved position.** If reading Saga's stored sign-in entries failed — which the secure-store can do transiently — the recovery wiped that whole store to start clean. The key that encrypts positions, history and settings lives in the same store, so the wipe would have made all of it unreadable from the next launch. Never observed in the wild; the recovery now discards only the sign-in entries. In the same family: most storage files responded to *any* error on opening by deleting themselves and starting fresh, which is right for a wrong-key case after a reinstall and wrong for a passing I/O error. History, collections, bookmarks and settings now only reset on genuine corruption, the rule the positions file has always followed.

### Security

A note on all of these: Saga's whole pitch is that your library stays yours, so the same question was asked of every other place a key to your Plex account could end up. Six answers came back. Only the first was caught before release; the rest have been in shipped builds, some since Saga could cast at all. Nothing here needs anything from you beyond installing the update, and none of it can be exploited from outside your own home network.

- **The Plex token could reach other apps on the phone through the media browse tree.** To appear in a car, Saga has to publish a browse service Android can bind to, and that service answers anything on the device that asks — no permission required. Covers in it were addressed by a URL carrying the token when the image wasn't already saved on the phone, which would have handed any app that looked a key to the whole Plex account, not just the audiobooks. Covers now come only from the copy already on the phone, downloaded with the token in a header where it can't be read back, and the same is true of the artwork on the lock screen. A cover the phone doesn't have yet is simply absent until the book is opened once. Caught before release: the browse tree ships for the first time in this version, so no released build ever exposed it.
- **Casting put your Plex token where everyone on the network could read it.** A Chromecast fetches the audio itself and can't send a password along with the request, so the key has to travel in the address — that part is unavoidable. What wasn't obvious is that a Chromecast will tell anyone on the same Wi-Fi what it's currently playing, address and all, without being asked to prove anything. So for as long as a book was casting, any device in the building could read a key to the whole Plex account: not just the audiobooks, the account. Saga now asks your server for a temporary pass that works on that one server and expires on its own, and casts with that instead. If your server is too old to issue one, Saga falls back to the account key rather than refusing to cast, and in that case it drops the cover art, so the key travels in one place instead of two.
- **Saga could settle on a plaintext connection to your server when an encrypted one was available.** Plex offers several routes to the same server and Saga tries them all at once, keeping the first that answers. First is not best: a plain connection on your own network replies before an encrypted one has finished proving who it is, so the quick one kept winning and every request afterwards carried your token in the open. Saga now waits for the answer that matters rather than the answer that's fastest, and takes the safest route that works — while still returning immediately when the best one is reachable, which is the normal case. It also no longer sends your token to routes it's only testing; finding out whether a server answers doesn't need it.
- **Every cover you'd ever seen left a copy of your token on the phone, and signing out didn't remove it.** Covers were fetched with the key written into the address, and the cover cache files them by address — so a working key sat in plain text in a database on the phone, for every book you'd ever scrolled past. Covers are now fetched with the key in a header instead, which the cache never sees. Installing this update clears the old entries once; your covers reload as you come across them. Signing out now also clears the cached covers, since they're a picture of your library. Your positions, history and downloads are deliberately kept — signing back in must never cost you your place.
- **Playing a streamed book started a small web server on the phone that other apps could reach.** It came from the audio library Saga uses, which starts one so it can attach your password to each request. Android never needed that — it can attach the password itself — so the server was doing nothing except making your audiobooks fetchable by any other app that went looking for it. It's gone. Two long-standing oddities went with it: a book could stop with an unexplained error in the log when your server's name failed to resolve, and stray requests to that port left noise behind.
- **The diagnostics log could still contain your server's address if you don't reach it by IP.** The masking added in 1.0.15 knew two shapes: a numeric address, and Plex's own `plex.direct` name. If you reach your server by a domain of your own, or over IPv6, the name came through intact — and the log is meant to be safe to paste into a public issue. Both shapes are now masked, wherever they appear, and as before the log is cleaned again when copied, so entries written by older versions are covered too.
- **The diagnostics log named your Chromecast and, occasionally, a narrator from your library.** Connecting to a cast device wrote the device's name, which is usually someone's own name or the room it sits in, and a failure while building the narrator index wrote the narrator's name, which is a piece of your library. 1.0.16 already established the rule for this when it started recording audio output by kind rather than by name; these two predated it. Neither is written any more.
- **The log knew two of the three shapes a failed connection takes.** A connection that times out quotes your server's address in a third form the masking didn't recognise, so someone reaching their server by their own domain name could still paste it into a public issue without knowing. The third shape is now masked like the other two, with a test pinning each one.
- **A garbled sign-in response could have shown your account key on screen.** If plex.tv answers the sign-in request with something unparseable, the resulting error quotes the reply — and the reply is where the account key lives. That error was printed raw on the sign-in screen, which is exactly the screen people screenshot for bug reports, and written to the log, whose masking didn't know the key's plex.tv spelling. The screen now shows a plain message, the log masks that spelling too, and the backup export/import messages stopped echoing raw errors for the same reason.

### Removed
- **Two unused build-time dependencies, `hive_generator` and `build_runner`.** They generate typed Hive adapters, and Saga has never had one — every box stores plain maps, and there is no `.g.dart` file in the project. They pulled in a large code-generation tree that was built and resolved on every checkout to produce nothing. No effect on the app itself; a faster, smaller build for anyone compiling from source.
- Dead code: an unreferenced screen left over from an earlier Home layout, and a notification icon set (plus a leftover three-spine vector from the previous logo) that nothing had pointed at since the launcher icons became generated.

## [1.0.17] - 2026-08-03

### Changed
- **The player's listening sessions show a 24-hour clock.** It was the one place in the app printing 8:30 PM rather than 20:30 — History and the per-book log have always used the 24-hour form.

### Fixed
- **Starting a book from a chapter, a bookmark or your history ignored its saved speed.** Saga keeps a playback speed per book, but only some of the ways into a book applied it: Resume and Play did, tapping a chapter in the book screen didn't. That book then played at whatever speed the *previous* book was using, or 1× from a cold start, with the speed button honestly reporting the wrong number it was actually playing. There is now one path from "you picked something" to audio, and it applies the speed before the first sound comes out, so there's no longer a list of entry points to remember. Same root cause as the speed display fixed in 1.0.14, on the other side of it.
- **The book screen showed how far through the current file you were, not the book.** For a book split into many files, the percentage and the "left" figure under the cover were measured against whichever file you were in — twelve files into a twenty-file book read as 2%, while Home, Browse and History all showed the truth.
- **A book whose length Plex doesn't report showed no length and no progress on its own screen.** Saga records a book's length itself the first time you play it, and Home has always fallen back to that; the book screen and the player's flipped cover only ever asked Plex. So a book could show a progress bar on Home and nothing at all on its own page. Both now use the recorded length when Plex has none, and a Plex length of zero no longer beats a real one.
- **History and Home could disagree about which week "this week" is.** Both show the same Monday-to-Sunday week, but History built it in fixed 24-hour steps, which is an hour short on the day the clocks go forward and an hour long when they go back. On those two days a year the week could shift by a day, and the totals with it — the same arithmetic behind the empty heatmap fixed earlier.
- **"Yesterday" could read as "Today", or as a bare date, when the clocks change.** Three screens each had their own way of turning a timestamp into "Today", "Yesterday" or a date, and all three counted in fixed 24-hour steps. On the days the clocks move, that made yesterday's bookmarks and listening sessions read as today's on two of them and as a plain date on the third.
- **A stream that died and couldn't be reloaded where it stopped no longer restarts the book.** If the automatic reload after a connection drop couldn't find the file your position belonged to, Saga fell back to the beginning and played from there. It now stops instead, leaving your place saved where it was.
- **Books storing their chapter titles scattered through the file showed none.** A chapter track keeps its titles as data sitting out among the audio, and Saga assumed they'd be stored together, fetching the stretch of file from the first to the last in one go. Nothing requires that: some tools store each title next to the audio it belongs to, so a nineteen-chapter book had its titles strewn across 626 MB, and Saga sensibly refused to pull in the whole book to collect a few hundred bytes. It now fetches them where they actually are, a few hundred bytes at a time, grouping any that sit close enough together to be worth taking in one go. Reported by [@Enagan](https://github.com/Enagan) ([#8](https://github.com/gaut3/saga/issues/8)).
- **A book whose chapter titles can't be read now keeps its chapters anyway.** The times were always there; only the names were out of reach. Rather than showing nothing, Saga now numbers them, so the chapter list and skipping still work even in the rare case where the titles are beyond reach. The diagnostics log says when this has happened, so it can't quietly pass for the real thing.
- **The diagnostics log said "no chapter track" when it had found one.** If the track was there but its titles couldn't be read, the log reported the same thing as a file with no chapters at all, which points the next person at entirely the wrong question.

## [1.0.16] - 2026-08-02

### Fixed
- **Long books showed no chapters at all, whatever format they were in.** To find chapters without loading a whole audiobook into memory, Saga read 8 MB from each end of the file and searched that. But an MP4 keeps an index of the audio itself, four bytes for every frame, and it sits in front of everything else — so at around thirteen and a half hours that index fills the entire 8 MB on its own and the chapters behind it were never reached. The length of the book was nowhere in the symptom: the same file that worked in other players simply came up empty here, and a shorter book from the same encoder was fine. Saga now steps through the file's structure instead, reading the sixteen bytes that describe each section and skipping the ones it doesn't need, so the audio index is stepped over rather than swallowed and the length of a book stops mattering. Found by [@Enagan](https://github.com/Enagan) ([#8](https://github.com/gaut3/saga/issues/8)), whose diagnostics pinned it to the byte.
- **A book could stop with nothing in the log to say why.** The pause that fires when headphones are unplugged wrote no diagnostics entry, so from the outside it was indistinguishable from a crash or a stall: the book simply wasn't playing any more. That pause is now recorded, along with changes to where audio is being sent — by device kind only ("bluetooth", "speaker"), never the device's name, which is usually someone's car or their own.
- **Opening a streamed book pulled megabytes just to look for chapters.** The same 8 MB-from-each-end approach ran against the server as two large range requests on every book open, even for a book with no chapters to find. Walking the structure needs a handful of small reads instead, so a book opens quicker and a book with nothing to find stops costing anything much.

## [1.0.15] - 2026-08-02

### Added
- **Tap the cover to look through it.** The artwork on the player screen drifts out of focus and the book's detail surfaces in its place — author, narrator, year, length, chapter count, publisher and the description — without leaving what you're listening to. The cover doesn't move or turn over; it recedes, and the glow it casts comes forward to fill the space. Tapping again brings it back, and "Full details" opens the book screen for the rest. The book title under the artwork still goes straight there, so there's a quick peek and a proper visit, and it's clear which is which.
- **Swipe the mini player away.** There was previously no way to dismiss it — once you'd played anything, the pill stayed for the rest of the session. It now goes with the same gesture as a notification in Android 16's shade: drag it slowly and it sticks in its slot, resisting, until it *snaps* free with a small rumble; from there it follows your finger and fades, and a spring either carries it off the screen or bounces it back into place. A quick flick sends it once it's free. Because it has to snap first, a stray sideways thumb can't stop your book. Your place is saved before anything else happens, so it's waiting in Continue Listening. Long-pressing the pill opens a menu with **Stop playback** for the same thing with a label on it.
- **Auto-play the next book.** Off by default; turn it on in Settings → Playback. When a book ends, the next one in its collection starts after a five-second countdown that you can cancel from the finished screen — and it works with the screen off, which is when books usually end. Only applies to books that are in a custom collection.
- **A live preview in the player animation setting.** Opening Settings → Player animation now shows a large mark actually moving in the mode you've selected, and switching between Reactive, Gentle and Pause updates it in place instead of closing the sheet. If a book is playing it previews the real audio.

- **Narrator and genre.** Who reads the book now appears under the author on the book screen and on the cover's revealed face, alongside genre tags. Plex has no narrator field of its own — audiobook libraries put it in **Style**, which is where Saga reads it from, so it appears for libraries tagged that way and is quietly omitted for those that aren't. Plex only sends these on a book's own record rather than in the library listing, so Saga fetches them the first time you open a book and remembers them from then on: no slower library load, and the details are still there offline.

- **Sort and search by narrator.** Browse gains a **Narrator** sort, and the search box now matches narrators as well as titles and authors. Because Plex doesn't include narrators in the library listing, Saga builds a lookup the first time you use either — one request per narrator in your library rather than one per book — with a progress bar while it runs. After that it's instant, and it's remembered. Books with no narrator tagged sort to the bottom rather than pretending to be first.

### Changed
- **Chapter reading now explains itself in the diagnostics log.** When a book's chapters don't appear, there was nothing to go on: a file that genuinely has none and a file Saga couldn't read looked exactly alike. Each attempt now records one line saying what it found in the file and where it gave up — which of MP4's chapter conventions is present, which tracks the file has, how much of the index Saga could reach. Settings → About → Copy diagnostics, and paste it into a report. The line holds atom names, counts and sizes only: no filename, no server address, nothing naming the book.

### Fixed
- **The diagnostics log could contain your server's address after all.** Entries are redacted as they're written, but only an address with `http://` in front of it was recognised. When the network layer itself fails it quotes the host on its own, with no scheme anywhere near it — and a Plex `plex.direct` name carries two secrets at once, since it's built from the server's public IP and its machine identifier. So a failed lookup wrote both into a log meant to be safe to paste into a public issue. Bare addresses in either form are now masked, as is the `plex.direct` name whole, and the log is redacted again when copied, so entries written by older versions are cleaned on their way out. The crash build id is deliberately kept: it's the same for everyone on a given release and it's what makes a stack trace readable.
- **Three crashes could bury everything else in the diagnostics log.** An uncaught error is recorded with its full native stack, around sixty lines each, against a budget of four hundred — so one bad afternoon could fill the log and leave no room for the weeks around it. Entries are now clipped to their first dozen lines, which is where the useful frames are, and each launch records the version it's running, so a copied log always says which build it came from and always has something recent in it.
- **The narrator and genre disappeared on the second launch.** Both are fetched once and cached, and the cache was correct — but on a cold start the stored record comes back from storage more loosely typed than it went in, and the tag reader was strict enough to silently discard every tag rather than fail. So a book showed its narrator on the day you opened it and never again, and reopening it didn't help: the cache had answered, just without them. The reader now accepts what storage returns.
- **The player screen could stay attached to the previous book.** Every screen that starts playback opens the player first and loads the book a moment later, so the player's first build saw whichever book was loaded before — and nothing rebuilt it afterwards, because the artwork and title arrive on a stream while the book's record was read just the once. From the second book of a session onwards you got the right cover with the wrong book behind it: the bookmarks pill counted and listed the earlier book's bookmarks, **Add bookmark** filed the new one under that book at this one's position, and the sessions pill showed the wrong history. The record is now read alongside the media item that changes with it, so every part of the screen is describing the same book.
- **M4B books storing their chapters as a chapter track showed none at all.** MP4 never settled on one way to store chapters, and Saga only read one of them — the Nero-style list. Files that instead carry a *chapter track* (a text track alongside the audio, which many tagging and conversion tools write) came up empty, while working fine in other players. Both forms are now read. Rarer conventions — OverDrive's XML markers, ID3 chapter frames — are still unsupported. Found while looking into a report from [@Enagan](https://github.com/Enagan) ([#8](https://github.com/gaut3/saga/issues/8)).
- **Chapters could be found in a downloaded book but not the same book streamed.** The streaming path was missing a fallback the local one had, so a file whose opening bytes couldn't be walked cleanly gave up instead of scanning for the chapter data. It also gave up entirely when the server didn't report the file size in the way it expected; it now accepts the other, more common way too.
- **Collection artwork was cropped top and bottom.** Collection tiles are slightly wider than they are tall, so square covers lost a slice off both edges. Covers are now shown whole against a blurred backdrop, the same treatment the player screen uses. The book screen's header artwork and the thumbnails in "Set cover" had the same problem — you were picking a cover from cropped previews — and are fixed too.
- **A new collection had no artwork until you went looking for it.** Adding the first book to a collection now adopts that book's cover automatically. Choosing a cover by hand still wins, and picking "None" is respected — it won't quietly come back on the next book you add.
- **"Show more" appeared under book descriptions with nothing more to show.** The toggle was drawn regardless of whether the text was actually cut off. It's now measured against the real width, so it only appears when there's something behind it.
- **A dropped stream resumed seconds away from where you were.** When the connection to the server hiccups mid-book, Saga quietly reloads and carries on. But it took the resume point from the saved bookmark, which is only written every ten seconds — and the save it does on the way past couldn't be waited for, so it read the *previous* value regardless. On a flaky connection that meant reappearing up to ten seconds from where you actually were. It now reloads from the live playback position.
- **Chapter lookups ran far too often while playing.** Resolving "which chapter is this?" — which happens on every position update, several times a second — rebuilt the entire chapter list from storage each time, allocating an object per chapter. On a book with a few hundred chapters that was constant needless work on the same thread that drives the animated mark and the audio meter. The list is now decoded once and reused.
- **The next-book button on the finished screen failed silently.** If the book couldn't be loaded — server unreachable, say — nothing happened at all, which looked exactly like a dead button. It now tells you.

## [1.0.13] - 2026-07-27

### Added
- **Playback resumes after phone calls and other interruptions.** When a call, alarm, or voice assistant pauses your book, playback now continues automatically once the interruption ends. Auto-resume is deliberately conservative: it fires only when the interruption looks call-like (the phone was ringing or in a call — including WhatsApp/Teams-style VoIP) or was a brief blip under 30 seconds (navigation prompt, notification sound). Another media app taking over — a video app, music — never triggers a resume, even if it releases the audio focus mid-session: resuming an audiobook over someone's video is worse than not resuming at all. Pausing manually during an interruption also cancels the auto-resume. Interruption decisions are recorded in the diagnostics log.
- **Scrub within the chapter.** New toggle in Settings → Playback: the player's seek bar covers only the current chapter instead of the whole book. On a 30-hour book, whole-book scrubbing moves minutes per pixel — chapter mode makes fine positioning actually possible. The time labels and drag tooltip switch to chapter-relative so the whole row speaks one unit, crossing a chapter boundary re-anchors the bar automatically, and multi-file books treat each file as a chapter. Off by default. Suggested by [@Kiffir](https://github.com/Kiffir) ([discussion #4](https://github.com/gaut3/saga/discussions/4)).
- **"Downloaded" filter chip in Browse.** Next to the existing "Saved" chip — shows only books with downloads on this device, including partially downloaded ones so you can find and finish them. Suggested by [@Kiffir](https://github.com/Kiffir) ([discussion #5](https://github.com/gaut3/saga/discussions/5)).
- **The player shows time remaining at your playback speed.** The label to the right of the scrubber now counts down the actual listening time left at the current speed — 2 hours of book at 1.5× shows as 1 h 20 m, the number that tells you whether you'll finish tonight. Tap it to switch to the book's total length.
- **Downloaded books now open and play without the server.** The track list was previously fetched from Plex on every book open, so even a fully downloaded book couldn't be opened offline. Track metadata is now stored locally when a book is downloaded (and refreshed on any online open of a downloaded book, which also covers books downloaded before this version), and used automatically whenever the server can't be reached. Deleting a download removes the stored metadata with it.

### Changed
- **Browse's filter/sort row redesigned.** Six identical-looking chips in a scrollable row mixed two different kinds of control — filters you can combine (Saved, Downloaded) and a pick-one sort. Filters now sit on the left as toggle chips; the four sort options collapse into a single chip on the right showing the active sort (e.g. "Title A→Z") that opens a bottom sheet — same pattern as the speed and sleep-timer pickers. Tap the active sort in the sheet to flip its direction. Nothing scrolls off-screen anymore, and the grid/list view toggle got the same pill styling as the chips so it reads as part of the row.

### Fixed
- **Browse grid: author names no longer crowd or clip under wrapped titles.** The grid cell reserved too little room for text, so a title that wrapped to two lines squeezed the author line — and author names sat at different heights from card to card. The title block now has a fixed two-line height and the cell is sized to fit it, so author names align across every row. Reported by [@Kiffir](https://github.com/Kiffir) ([#3](https://github.com/gaut3/saga/issues/3)).
- **Browse and the "Downloaded books" list could disagree about what's downloaded.** The Settings storage list was built by scanning download folders on disk, while Browse's badge and filter read the download records — and the storage list's delete button removed folders *without* updating those records, so a book deleted there kept showing as downloaded in Browse forever (and vanished from the storage list, having no folder). Both surfaces now read the same records: the storage list is built from them, its delete goes through the same path as every other delete (files, records, and badges all update together), and at startup Saga reconciles records against the actual files — so any stale "downloaded" books from previous versions clean themselves up on first launch. This also fixes the per-file checkmarks in a book's chapter list staying lit after deleting its download. Thanks to [@Kiffir](https://github.com/Kiffir) for spotting this one too!
- **The "Downloaded books" list in Settings updates without restarting the app.** The storage overview scanned the disk once and then kept that result for the entire app session, so books downloaded or deleted afterwards didn't show until the app was fully closed and reopened. It now re-scans whenever a download completes or a book is deleted. Thanks to [@Kiffir](https://github.com/Kiffir) for the report ([#2](https://github.com/gaut3/saga/issues/2))!
- **Long streamed listening sessions could stall with the screen off.** The player held a CPU wake lock while playing but never a Wi-Fi lock, so on phones with aggressive Wi-Fi power saving, a multi-hour streamed book could starve its buffer once the screen had been off for a while. The player now requests network-aware wake behavior (ExoPlayer's network wake mode), which holds a Wi-Fi lock for the duration of network playback. Downloaded books were never affected.
- **Media notification controls went dead after the app sat paused in the background for a while.** Android eventually kills a paused app's process to reclaim memory (aggressively so on some phones), but the media card in the notification shade lives on. Tapping its play button restarted Saga's audio service — which woke up with no memory of what it had been playing, so nothing happened. The service now restores the session on such a play command: it reloads your most recently listened book at the saved position (with the usual smart rewind and your saved playback speed) and starts playing. Works offline for downloaded books; for streamed books the Plex server needs to be reachable.
- **The "Downloaded books" tile in Settings now follows theme changes.** It was built as a `const` widget, so switching theme repainted every other tile on the screen except this one, which kept its original colors until the screen was reopened.
- **The "downloaded" cover badge no longer appears for partially downloaded books.** The badge showed as soon as one file finished, which for a 20-file book was misleading — especially if you went offline trusting it. It now appears only when every file of the book is downloaded. (Books downloaded with older versions keep the old behavior until their first online open, which records the expected file count.)
- **Backgrounding the app while a book was still buffering could freeze the stream.** Starting playback only promoted the app to a foreground service *after* the stream from Plex had finished its initial load — so during that window (several seconds on a slow connection) Saga was an ordinary background app, which Android is free to suspend the moment you switch away. Suspended mid-buffer, the connection to the server simply stopped until you came back. Playback intent is now declared before the network load begins, while the app is still on screen: the foreground service and its wake lock are up for the entire buffer, so switching away during "the spinner" no longer stalls the stream. Side benefits: the media notification now shows the book's details immediately instead of appearing empty until loading finishes, and books now resume directly at the saved position instead of loading at zero and seeking after.

## [1.0.11] - 2026-06-12

Stability and hardening release from a full codebase audit.

### Added
- **Local diagnostics log + "Copy diagnostics".** Errors are now recorded to a small local log — no telemetry, nothing is transmitted; the log only leaves the device when you tap the new **Settings → About → Copy diagnostics** tile. Covered: crashes, playback stream failures and the automatic reload after them, failed book loads, download failure reasons (the UI only said "Retry N failed", never why), Cast session activity, token rejection by the server (explains any surprise sign-out), server re-discovery after a stale address, backup import/export failures, and the position store's wipe-on-corruption decision. Entries are redacted at write time: the Plex token and any server address are masked before a line ever reaches disk, so a pasted bug report can't leak credentials.
- **Cast failures now say why.** When a Cast session fails to start, the sheet shows an error toast with the Cast SDK's reason (e.g. "TIMEOUT (15)") instead of silently returning to the device list. The reason is also written to the diagnostics log. Normal disconnects are not flagged — the SDK reports a reason code even when you end the session yourself, which is logged but never shown as an error.

### Changed
- **Adding a bookmark is now a bottom sheet — with a note field.** The Bookmark button opened an `AlertDialog` while *editing* a bookmark used a sheet; creating and editing the same thing now share one surface. Bonus: the note field is available at creation time instead of only when editing afterward.
- **Playback speed is now a picker sheet.** The speed button cycled through presets one tap at a time (five taps to get from 1.0× to 2.5×, easy to overshoot). It now opens a sheet listing all speeds with the current one marked — same pattern as the sleep-timer picker, making every player action-row button open a sheet.
- **Consistent error states on every screen.** Home, Browse, Authors, Collections, In Progress, and the library book list now share one error view: a friendly message with a Retry button. Previously each tab did its own thing — Browse had no retry, and Authors/In Progress displayed the raw exception text, which could include your server's address (the kind of thing that ends up in screenshots attached to bug reports). Raw error details now go to the diagnostics log instead of the screen.
- **Every bottom sheet now has a drag handle and a consistent title.** The handle is applied automatically by the shared sheet, replacing three hand-rolled variants (one was a different size and opacity); sheet titles were split between two sizes and three font weights and are now one shared style.
- **Text consistency pass.** "Sign Out" → "Sign out", "Active Library" → "Active library", "Data & Backup" → "Data & backup", "Plex Server" → "Plex server", "New Collection" → "New collection", "Select Library" → "Select library" (sentence case app-wide); trailing periods removed from one-line empty states.
- **Cast device search shows the Saga mark.** While scanning for Chromecast devices, the sheet shows the brand buffering animation instead of a stock spinner, matching the connecting state.
- **Cast device picker is now a native Saga sheet.** Choosing a Chromecast no longer opens the old system-style dialog; devices appear live inside the same bottom sheet as the rest of the app, with a searching indicator while discovery runs. Device discovery now also stops when the sheet closes (active scanning costs battery).

### Fixed
- **Chromecast never actually played anything.** Selecting a device started a Cast session but the app never handed the audio over — and even if it had, the stream URL carried no auth token (the Cast device fetches the URL itself and can't send headers, so Plex would have refused it) and the content type was hardcoded to MP3 (wrong for M4B). Casting now pauses local playback, loads the current track on the device at the current position with the correct MIME type, cover art, and a tokened stream URL. Disconnecting pulls the position back from the Cast device and seeks the local player there, so you resume exactly where the cast left off. Failed session starts now also report back instead of leaving the UI stuck on "connecting". Known limitation: one track is cast at a time — for single-file M4B books that's the whole book; multi-file books don't auto-advance to the next file yet.
- **Position saves are now durable on app kill.** Bookmark writes were fire-and-forget; the app could be killed by Android in the window between scheduling the write and it reaching disk — exactly the moment lifecycle saves exist for. All position, completion, and offline-sync-queue writes are now awaited through the save path (`_saveAndReportPosition`, `savePosition`, `savePositionForLifecycle`, `pause`, `stop`).
- **Rapidly switching books could silently stop position saving.** If a book load was interrupted by loading another book and then failed, its error handler wiped the *new* book's state, so every subsequent position save was silently dropped until the next load. `loadBook` now uses a generation counter: a superseded load can no longer clobber the active book's state.
- **Opening a downloaded book no longer loads the entire file into memory.** The chapter parser read the whole M4B (often hundreds of MB) into RAM to find the chapter atom — an out-of-memory crash risk on low-RAM devices. It now reads at most 8 MB from the head and 8 MB from the tail, matching the streaming path's strategy.
- **Playback event listeners can no longer die silently.** Six audio stream listeners (track index, position, completion detection, headphone-unplug, audio interruptions, sleep-timer playback watch) had no error handlers; a single stream error would cancel the subscription for the rest of the session — e.g. book completion would silently stop being detected. All now carry error handlers.
- **A malformed Plex track no longer crashes the whole track list.** `PlexTrack` parsing crashed on items with a missing `key` or `title` (partially-indexed files). Same bug class as the book-title parse crash fixed in 1.0.2; now null-guarded.
- **Sign-out dialog popped the wrong screen.** The Settings sign-out confirmation used the settings screen's navigator context instead of the dialog's own — the same navigator-layer bug fixed in five other dialogs previously. Cancel/Sign out now close only the dialog. The player's Add Bookmark dialog had the same latent pattern and was fixed for consistency.
- **Failed downloads no longer leave partial files on disk.** A download that failed mid-transfer left the partial file orphaned — never played, but invisibly consuming storage (the storage manager only lists completed downloads). The partial file is now deleted on failure.
- **Network requests can no longer hang indefinitely on connect.** The PIN sign-in flow, server discovery probes, artwork prefetch, and chapter fetch all created Dio clients without a connect timeout; a stalled TCP connect could hang sign-in forever. All now fail fast (5–10 s).
- **Malformed chapter timestamps are rejected.** A corrupt M4B chapter entry with an out-of-range timestamp could produce a negative chapter start time; it is now clamped to zero.
- **Settings toggles no longer risk a crash when leaving the screen mid-tap.** Several async settings callbacks (skip intervals, speed, auto-rewind, Wi-Fi-only, redact address, animation delay, library picker, Up Next nudge dismiss, bulk add-to-collection) called `setState`/providers after an await without checking the widget was still mounted.

### Removed
- Dead code: an unused legacy library screen (unreferenced since the settings redesign) was deleted.

## [1.0.3] – 2026-06-06

### Security
- **Cross-server backup restore now warns before proceeding.** Plex `ratingKey` values are per-server integers — importing a backup from a different server could silently overwrite positions for unrelated books that share the same integer key. The app now persists the connected server's `machineIdentifier` (stored in the Android Keystore alongside the token) and embeds it in every backup export (format v4). On restore, if the backup's server ID is present and differs from the current server's, a warning dialog is shown before any data is written.
- **Backup temp file is deleted after sharing.** The JSON export was written to the system temp directory and left there after `Share.shareXFiles()` returned. The file is now deleted immediately after the share sheet is dismissed.
- **CodeQL static analysis added.** `.github/workflows/codeql.yml` runs on every push/PR to `main` and weekly. It analyzes the Android/Kotlin layer (the RMS audio patch, platform channels, native plugins) using the `security-and-quality` query pack, catching taint flows, crypto misuse, and injection risks that Dart-level analysis cannot see.

### Fixed
- **Streak shows 0 before you've listened today, even if yesterday's streak is intact.** Both `_homeStreak()` (home screen strip) and `_computeStreak()` (history screen) started walking backwards from today — if today has no listening time yet the loop exits immediately, reporting 0. They now start from yesterday when today is empty, so the streak stays visible all day until you either extend it or midnight passes. Also applied the DST midnight-renormalization fix to `_homeStreak()` (missed in 1.0.2).
- **Download mark no longer stays frozen at the bottom.** The progress passed to `AnimatedSagaMark` was a whole-track count (`downloadedCount / total`), which stays at 0.0 for the entire download of a single-file audiobook. It now incorporates the actual byte-level progress reported by Dio, so the bars fill smoothly from floor to full. The button label also now shows a percentage (`Downloading 34%…`) instead of `Downloading 0 / 1…`.
- **Playback speed resets to default when resuming from the Continue Listening card.** The home screen's Resume card called `loadBook()` and `play()` without restoring the per-book saved speed, so a book set to 2× would silently drop back to the global default on the next resume. Both the resume-and-play path and the load-only (open player) path now restore speed identically to the book detail Resume button. Same fix applied to the stream-error auto-reload path in `player_provider.dart`.
- **Today's bar in the home weekly sparkline could show the wrong colour on DST transition days.** The seven `weekDays` entries were built with `Duration(days: N)` additions without renormalizing to midnight. Across a spring-forward boundary the time component drifts to 01:00, causing the `isToday` equality check to fail and today's bar to appear as a past-day colour. Each entry is now renormalized to midnight after the addition (same pattern as the existing `monday` renormalization above it).
- **"Avg / day" in the Month history tab showed an inflated average.** The stat divided total listening time by the number of days the user actually listened, not by the number of days in the month. A user who listened on 3 of 30 days would see roughly 10× the true daily average. The denominator is now `daysInMonth`, matching what the label says.
- **Global download indicator added.** A 3 px accent-colored progress bar appears at the top of the bottom bar (above the mini player) on every screen while a download is active, so there is always a visible signal that something is downloading even after leaving the book detail screen.
